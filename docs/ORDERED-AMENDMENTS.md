# Ordered amendment source evidence

`python -m law_history --repository PATH ordered-operations REFID --product PRODUCT_ID`

This versioned interface (`history-ordered-amendment-evidence-v2`) reads a verified existing operation product and its exact retained XML. It leaves v1 products and retrieval unchanged. The result retains the complete mixed-content body tree: every element, attribute, character-data run and sibling path. Images and formulas remain source elements, not silently omitted text. This interface returns evidence data, not rendered or legally qualified replacement text.

Every parsed operation remains present, including empty repeal text and ambiguous instruction matches. Every raw body block remains available even when no producer operation matched or the act has zero parsed operations. The complete body also retains structures outside that block inventory. Uniquely matched instructions expose their trees and immediately following source-tagged replacement trees; adjacency is a candidate association, not proof of replacement scope. Targets, timing and semantic operation completeness remain unresolved.

The evidence identity hashes the entire deterministic result. Each occurrence carries its member hash, observation, knowledge clocks and exact paths. A real retained amendment (`forskrift/2025-05-28-955`) retrieves the complete replacement provision with `218,62` and inline structure. Source association and reconstruction must still qualify whole/partial targets, insertion, repeal, renumbering, movement and commencement. This interface alone does not complete plan step 4 or enable legal-date answers.
